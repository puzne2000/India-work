# הוראות בנייה — מכתב דיקן כקובץ Word (.docx)

מדריך טכני כללי (לא תלוי-מועמד) לבניית מכתב דיקן לאישור סוקרים, על נייר המכתבים הרשמי.
השיטה הזו שימשה לבניית הטיוטה של ברק רווה, ומיועדת לשימוש חוזר לכל מועמד.

## עיקרון
לוקחים את תבנית ה-Word `תבנית/תבנית-מכתב-דיקן-גיא-קינדלר.docx` (שנושאת את נייר המכתבים,
הלוגו והכותרת/כותרת-תחתונה עם החתימה של פרופ' גיא קינדלר), ומחליפים **רק את גוף המסמך**
(`word/document.xml`), תוך שמירה על ה-header/footer וה-`<w:sectPr>`.

## שלבים

1. **פריסה (unzip):** פרסו את קובץ התבנית לתיקייה זמנית (בתיקיית ה-scratchpad, לא בפרויקט):
   ```bash
   unzip -q "מכתבים/תבנית/תבנית-מכתב-דיקן-גיא-קינדלר.docx" -d tpl/
   find tpl -type l -delete   # הסרת קישורים סימבוליים (קובץ חיצוני = לא אמין)
   ```

2. **בניית גוף חדש ל-`tpl/word/document.xml`:**
   - שמרו את כל מה שעד `<w:body>` ואת ה-`<w:sectPr>...</w:sectPr>` (הוא מפנה ל-header rId8
     ול-footer rId9 — אל תיגעו בהם). החליפו רק את הפסקאות שביניהם.
   - אל תיגעו ב-`word/header1.xml`, `word/footer1.xml`, ב-`_rels`, או ב-`word/media/` (הלוגו).
   - **פסקאות עברית (RTL) — יישור לימין:** `<w:pPr><w:bidi/>...`, **בלי** `<w:jc>`,
     וב-runs הוסיפו `<w:rtl/>`. פסקת `<w:bidi/>` ללא `<w:jc>` מיושרת כברירת-מחדל ל"התחלה"
     של כיוון הקריאה = הימין הפיזי (גם ב-Word וגם ב-LibreOffice). זה היישור הנכון לגוף המכתב.
   - **⚠️ מלכודת RTL קריטית (אל תשתמשו ב-`<w:jc w:val="right"/>` לעברית):** בתוך פסקת
     `<w:bidi/>`, גם Word וגם LibreOffice מפרשים את `<w:jc w:val="right"/>` כ"סוף" הלוגי,
     כלומר **שמאל פיזי** — כך שכל גוף המכתב יוצא מיושר לשמאל. לכן לעברית משאירים בלי `<w:jc>`
     (ראו למעלה). היפוכו של דבר: כדי ליישר שורה עברית ל**שמאל** (למשל שורות התאריך, לפי
     מוסכמת מכתב הדוגמה של סטנובסקי — תאריך בשמאל למעלה, שאר הגוף בימין), דווקא כן מוסיפים
     `<w:jc w:val="right"/>` (=שמאל פיזי).
   - **פסקאות אנגלית (רשימת הסוקרים, LTR):** `<w:pPr><w:bidi w:val="0"/>...<w:jc w:val="left"/>`,
     ללא `<w:rtl/>` (כאן `left`=שמאל פיזי, כי הפסקה LTR). ניתן לרכז שדות של סוקר בפסקה אחת
     עם `<w:br/>` בין השורות.
   - **פונט:** Times New Roman, גודל `<w:sz w:val="24"/>` (12pt). כותרת "הנדון" מודגשת (`<w:b/><w:bCs/>`).
   - **חובה לברוח (escape)** מתווים בטקסט: `&`→`&amp;`, `<`→`&lt;`, `>`→`&gt;` (חשוב במיוחד
     ב-URL של Google Scholar שמכילים `&`).
   - הכי בטוח: לייצר את ה-XML בסקריפט Python קצר (helper לפסקת עברית / פסקת אנגלית) במקום
     בעריכה ידנית.

3. **אריזה מחדש (rezip):**
   ```bash
   (cd tpl && rm -f ../out.docx && zip -Xrq ../out.docx .)
   ```

4. **אימות סכימה (חובה):**
   ```bash
   pip install -q lxml defusedxml   # אם חסרים
   python3 /root/.claude/skills/docx/scripts/office/validate.py out.docx \
     --original "מכתבים/תבנית/תבנית-מכתב-דיקן-גיא-קינדלר.docx"
   ```
   יש לוודא "All validations PASSED". הערה: על Windows הריצו עם `PYTHONUTF8=1` (אחרת
   ה-validator נכשל על קידוד cp1252), ונתיב ה-`validate.py` תלוי-סביבה — אתרו אותו תחת
   `skills/docx/scripts/office/validate.py`.

5. **אימות פריסה חזותי (חובה — כי אימות סכימה לא תופס יישור):**
   רנדרו ל-PDF ומדדו את מיקום הטקסט, אל תסתמכו על העין בלבד (טקסט RTL מטעה):
   ```bash
   soffice --headless --convert-to pdf --outdir <scratch> out.docx   # LibreOffice מותקן
   # ואז עם pymupdf: השוו x0/x1 של כל שורה לרוחב העמוד — עברית צריכה לגעת בשוליים הימניים
   # (x1≈רוחב-העמוד פחות שוליים), התאריך בשוליים השמאליים (x0≈שוליים שמאליים), אנגלית משמאל.
   ```
   זו הדרך היח­ידה לוודא שהיישור נכון לפני שמוסרים למשתמש (ראו מלכודת ה-RTL בשלב 2).

6. **פלט:** שמרו את הקובץ הסופי ב-`מכתבים/טיוטות/מכתב-דיקן-אישור-סוקרים-<שם>-טיוטה.docx`.

## מגבלות סביבה
- **רינדור ל-PDF זמין** (LibreOffice `soffice` מותקן). המירו ל-PDF ורנדרו לתמונה עם
  `pymupdf` (`get_pixmap`) כדי לבדוק את הפריסה בפועל — כולל יישור RTL. אל תסתמכו רק על
  אימות הסכימה; הוא לא בודק יישור.
- קבצים זמניים (unzip/rezip/render) — בתיקיית ה-scratchpad בלבד, לא בתוך הפרויקט.

## מבנה תוכן המכתב
ראו `ניתוח-מבנה-מכתב-משאל-סוקרים.md` (סעיפים 1–10) ואת מכתב הדוגמה/הטיוטה של ברק רווה
(`טיוטות/מכתב-דיקן-אישור-סוקרים-ברק-רווה-טיוטה.docx`) כמודל לפריסה ולנוסח.
